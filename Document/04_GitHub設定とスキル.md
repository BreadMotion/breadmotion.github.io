### 利用可能な用途

GitHub Actions により、以下の自動化が可能です：

#### CI（継続的インテグレーション）

- コード品質チェック
  - Linting（ESLint、Prettier等）
  - テスト実行（Jest、Mocha等）
  - ビルド検証
- セキュリティスキャン
  - 依存パッケージの脆弱性チェック
  - Secret スキャン

#### CD（継続的デプロイメント）

- 自動デプロイ
  - Webサイトの自動ビルド・デプロイ
  - GitHub Pages での自動公開
- リリース自動化
  - タグ作成時の自動ビルド・リリース

#### その他

- ドキュメント自動生成
- スケジュール実行（定期更新）
- PR チェック（マージ前の自動検証）

### ワークフロー追加時の注意事項

今後ワークフローを追加する場合：

1. `.github/workflows/` に YAML ファイルを作成
2. GitHub 標準的な命名規則に従う（例: `ci.yml`, `deploy.yml`）
3. トリガー条件を明確に定義（push, pull_request, schedule等）
4. 各ジョブの目的を明記

## スキル定義

### 利用可能なスキル一覧

| スキル名 | 説明 | 用途 |
|---------|------|------|
| **github-actions-failure-debugging** | 失敗したGitHub Actionsのデバッグ | ワークフロー実行失敗時の原因究明 |

### github-actions-failure-debugging スキル

#### 概要

このスキルは、GitHub Actions ワークフローの実行失敗をデバッグするための支援ツールです。

**管理者**: GitHub Copilot
**利用可能な環境**: GitHub Copilot CLI

#### 主な機能

このスキルを使用すると、以下のデバッグ業務を自動化できます：

1. **ワークフロー実行状況確認**
   - 失敗したワークフロー実行のリスト取得
   - 各実行のステータス確認
   - 失敗したジョブの特定

2. **ジョブログ要約**
   - ジョブログの自動取得
   - エラーメッセージの要約
   - 失敗原因の候補抽出

3. **詳細ログ取得**
   - 特定ステップのログ詳細表示
   - スタックトレースの整理
   - 環境情報の確認

4. **ローカル再現**
   - 失敗条件のローカル環境での再現方法提示
   - 再現手順のドキュメント化
   - デバッグの効率化

5. **修正確認**
   - 修正内容の検証
   - ワークフロー再実行
   - 問題解決の確認

#### トリガー条件

以下の条件でこのスキルの利用が推奨されます：

- GitHub Actions ワークフロー実行が失敗した
- ワークフローのジョブログが複雑で原因がわかりにくい
- 同じワークフローの失敗が繰り返されている
- ローカルでの再現・検証が必要な場合

#### 使用方法

GitHub Copilot CLI で以下のように指示：

```bash
copilot help github-actions-failure-debugging
# または、キーワードで検索
copilot search "workflow debug"
```

#### 実行フロー

```
失敗通知
  ↓
ワークフロー状況確認
  ↓
ジョブログ要約
  ↓
詳細ログ取得
  ↓
ローカル再現条件提示
  ↓
修正提案・確認
  ↓
再実行検証
```

#### サンプルシナリオ

**シナリオ**: ビルドステップが失敗した場合

1. 失敗したワークフロー実行を特定
2. ビルドジョブのログを取得
3. エラーメッセージを抽出（例: "モジュールが見つかりません"）
4. 依存パッケージのインストール手順を確認
5. ローカルで `npm install` を実行して再現
6. 修正内容をコミット
7. ワークフロー再実行で確認

## スキル定義の管理

### スキル定義ファイル

プロジェクト内のスキル定義は以下の場所に配置されます：

```
プロジェクトルート/
└── .copilot/
    └── skills/
        └── github-actions-failure-debugging.yml（またはJSON）
```

（**注**: 具体的な管理方法はプロジェクト設定に依存）

### 新規スキル追加時

1. スキルの目的を明確に定義
2. スキルファイルを作成
3. ドキュメントに記載
4. GitHub Copilot CLI で登録

## 運用上の注意事項

### GitHub Actions 導入時

1. **段階的導入**
   - 最初は単純な自動化から（Linting, テスト等）
   - 段階的に複雑なパイプラインへ
   - 各ステップで十分にテスト

2. **ジョブ実行時間の最適化**
   - キャッシュの活用（依存パッケージ等）
   - 並列実行の設定
   - 不要なステップの削除

3. **通知・アラート**
   - 失敗時のアラート設定
   - Slack等との連携
   - チームへの通知

4. **ログ管理**
   - ログの保持期間を明確に
   - 機密情報がログに残らない確認
   - ログの検索・分析

### デバッグ時のベストプラクティス

1. **github-actions-failure-debugging スキル利用**
   - 複雑な失敗の場合は積極的に活用
   - ログ解析の手作業を削減

2. **ローカルテスト**
   - act（GitHub Actions ローカル実行ツール）の利用
   - 本番実行前に十分なテスト

3. **バージョン管理**
   - ワークフローファイルもバージョン管理対象
   - 変更履歴を追跡可能に

4. **ドキュメント**
   - ワークフローの目的を明記
   - トリガー条件、必須環境変数を記載
   - トラブルシューティングガイドを作成
