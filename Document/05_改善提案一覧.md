## 2. 参考サイト（Leon Gameworks）から学ぶデザイン改善

### Leon Gameworks の優れた点
- 黒基調 + 半透明白文字で情報階層が明確
- `uppercase` と広めの letter-spacing でコーポレート感が強い
- `max-width` を抑えた余白設計で読みやすい
- 固定ヘッダーが `backdrop-blur` 付きで、常に現在地を見失いにくい
- ヒーローが「1行で価値を伝える」構成になっている
- カードUIで実績・事業・採用情報を整理している
- スクロール時の段階表示で静的サイトでも情報密度を軽く見せている

### Leon提案 #L1 | 固定ヘッダー + ガラスモーフィズムの完成度を上げる
- **見習う箇所**: 参考サイトの固定ヘッダーと `bg-black/70 + backdrop-blur` の見え方
- **現状**: `layout.css` の `.site-header` は `position: sticky` と `backdrop-filter: blur(12px)` をすでに持つ
- **改善方針**: スクロール量に応じて高さ・透明度・影を切り替え、視認性を安定させる

```css
.site-header {
  position: sticky;
  top: 0;
  background: rgba(10, 10, 14, 0.72);
  backdrop-filter: blur(16px);
  border-bottom: 1px solid rgba(255, 255, 255, 0.08);
}

.site-header.is-scrolled {
  background: rgba(10, 10, 14, 0.88);
  box-shadow: 0 12px 32px rgba(0, 0, 0, 0.28);
}
```

### Leon提案 #L2 | 強いキャッチコピーの1行ヒーロー化
- **見習う箇所**: “Make Games. Ignite Excitement.” のような一発で伝わるコピー
- **現状**: `index.html` は肩書きはあるが、サイト価値を一文で言い切れていない
- **改善方針**: 「誰に」「何を」提供するかを1行で明示する

```html
</section>
```

### Leon提案 #L4 | セクション順を「自己紹介→実績→ブログ→問い合わせ」に寄せる
- **見習う箇所**: 信頼形成 → 実績 → 行動喚起の順序

### Leon提案 #L5 | スクロールアニメーションを `IntersectionObserver` で統一する
- **見習う箇所**: ScrollReveal 的な段階表示
- **現状**: `base.css` に `.reveal-on-scroll` はあるが、実装品質を揃える余地がある
- **改善方針**: `prefers-reduced-motion` に配慮しつつ一元化する

```js
const observer = new IntersectionObserver((entries) => {
  entries.forEach((entry) => {
    if (entry.isIntersecting) entry.target.classList.add('is-visible');
  });
}, { threshold: 0.15 });

document.querySelectorAll('.reveal-on-scroll').forEach((el) => observer.observe(el));
```

## 3. HIGH優先度改善提案

### 改善 #H1 | `portfolio.html` の `noindex` を解除する
- **対象**: `WebSite\portfolio.html`
- **確認済み問題**: `<meta name="robots" content="noindex">` が入っており、作品一覧ページが検索流入対象から外れている
- **影響**: ポートフォリオページが検索結果に出にくく、成果物の発見性を大きく落とす
- **対応方針**: 公開作品として見せる前提なら `noindex` を削除し、`index,follow` を許可する

```html
<!-- 修正前 -->
<meta name="robots" content="noindex">

<!-- 修正後 -->
<meta name="robots" content="index,follow">
```

- **優先度が高い理由**: SEO上の致命傷で、実装コストより損失の方が大きい

### 改善 #H2 | `header.html` にスキップリンクを追加する
- **対象**: `WebSite\partials\header.html` と各ページの `<main>`
- **確認済み問題**: スキップリンクがなく、キーボード利用者が毎回ヘッダー操作を通過する必要がある
- **影響**: WCAG 2.4.1 の観点で不利。トップページ・ブログ・ポートフォリオで体験差が大きい
- **対応方針**: ヘッダー直前にスキップリンク、各ページの main に `id="main-content"` を付与

```html
<a href="#main-content" class="skip-link">メインコンテンツへスキップ</a>
<header class="site-header">...</header>
<main id="main-content" class="main-container">...</main>
```

```css
.skip-link {
  position: absolute;
  left: 1rem;
  top: -3rem;
  padding: 0.75rem 1rem;
  background: #111;
  color: #fff;
  z-index: 1000;
}

.skip-link:focus {
  top: 1rem;
}
```

### 改善 #H3 | `nav-toggle` に `aria-expanded` / `aria-controls` を付ける
- **対象**: `WebSite\partials\header.html`, `WebSite\assets\js\layout.js`
- **確認済み問題**: モバイルメニューボタンに状態公開がなく、支援技術から開閉状態が読み取れない
- **影響**: WCAG 4.1.2 に直結。モバイル利用時の情報欠落が大きい
- **対応方針**: ボタンとナビをIDで関連付け、JSで `aria-expanded` を同期更新する

```html
<button
  class="nav-toggle"
  type="button"
  aria-label="メニューを開閉"
  aria-expanded="false"
  aria-controls="global-nav">
  <span class="nav-toggle__icon" aria-hidden="true"></span>
</button>

<nav id="global-nav" class="site-nav">...</nav>
```

```js
const navToggle = document.querySelector('.nav-toggle');
const siteNav = document.querySelector('.site-nav');

navToggle.addEventListener('click', () => {
  const isOpen = siteNav.classList.toggle('is-open');
  navToggle.setAttribute('aria-expanded', String(isOpen));
});
```

### 改善 #H4 | 画像を WebP 化し、`srcset` / `sizes` を付与する
- **対象**: 全ページの OGP 以外の表示画像、特にカード画像・作品画像・記事画像
- **確認済み問題**: `srcset` / `sizes` / `width` / `height` が不足し、モバイルでも大きい画像を取りに行きやすい
- **影響**: LCP・転送量・CLS に悪影響
- **対応方針**: `picture` とレスポンシブ画像を標準化する

```html
<picture>
  <source
    type="image/webp"
    srcset="assets/img/work-480.webp 480w, assets/img/work-960.webp 960w"
    sizes="(max-width: 768px) 100vw, 50vw">
  <img
    src="assets/img/work-960.jpg"
    width="960"
    height="540"
    loading="lazy"
    decoding="async"
    alt="作品サムネイルのプレビュー">
</picture>
```

- **優先度が高い理由**: 全ページ横断で効くうえ、GitHub Pages 構成でも実施しやすい

### 改善 #H5 | `blog.html` のフィルターUIへ `label` と `aria-controls` を追加する
- **対象**: `WebSite\blog.html`
- **確認済み問題**: フィルター見出しが `span` で、`select` / `input` に明示ラベルがない。さらに一覧がJS依存で静的HTML上は空
- **影響**: アクセシビリティ低下 + JS失敗時に一覧が何も見えない
- **対応方針**: `label for`、`aria-controls="blogList"`、空状態に `role="status"`、`noscript` フォールバックを追加する

```html
<div class="blog-filter">
  <label for="blogCategoryFilter" class="blog-filter__label">カテゴリ</label>
  <select id="blogCategoryFilter" aria-controls="blogList">
    <option value="">すべて</option>
  </select>
</div>

<div class="blog-filter">
  <label for="blogSearch" class="blog-filter__label">検索</label>
  <input type="search" id="blogSearch" aria-controls="blogList" placeholder="タイトル・概要・タグで検索">
</div>

<p id="blogEmptyMessage" role="status" class="text-muted" hidden>条件に一致する記事がありません。</p>
<noscript><p>JavaScript無効時は <a href="blog/blog_00001.html">記事一覧</a> から参照してください。</p></noscript>
```

### 改善 #H6 | `products.html` を整理し、リダイレクト専用ページ運用をやめる
- **対象**: `WebSite\products.html`
- **確認済み問題**: `meta refresh` による即時リダイレクトのみで、OGP・本文・導線価値がほぼない
- **影響**: ユーザーにも検索エンジンにも曖昧なページになる
- **対応方針**: 役割を `portfolio.html` に統合し、`products.html` は廃止または軽量案内ページへ変更する

```html
<!-- 修正前 -->
<meta http-equiv="refresh" content="0; url=portfolio.html">

<!-- 修正後の案内ページ例 -->
<main class="main-container">
  <h1>Products は Portfolio に統合しました</h1>
  <p>最新の作品一覧は Portfolio ページでご覧ください。</p>
  <p><a href="portfolio.html" class="btn btn-primary">Portfolioへ移動</a></p>
</main>
```

- **補足**: ヘッダーやフッター内のリンクも `portfolio.html` に統一する

### 改善 #H7 | `contact.html` に `autocomplete` と `aria-describedby` を追加する
- **対象**: `WebSite\contact.html`
- **確認済み問題**: `label for` は正しいが、`novalidate` のまま補助説明や入力補完が弱い。電話番号にも `autocomplete` がない
- **影響**: 入力負荷増、モバイル送信率低下、エラー理解不足
- **対応方針**: 各入力に補助テキストIDを付け、ブラウザ補完を活かす

```html
<p id="emailHelp" class="form-help">返信先として使用します。</p>
<input
  type="email"
  id="email"
  name="email"
  class="input"
  autocomplete="email"
  aria-describedby="emailHelp"
  required>

<p id="phoneHelp" class="form-help">任意です。半角数字で入力してください。</p>
<input
  type="tel"
  id="phone"
  name="phone"
  class="input"
  autocomplete="tel"
  inputmode="tel"
  pattern="[0-9\-\+\s]{8,15}"
  aria-describedby="phoneHelp">
```

### 改善 #H8 | JavaScript の読み込み順を見直し、`defer` / 条件分岐を徹底する
- **対象**: `index.html`, `blog.html`, `portfolio.html`, `products.html`, `contact.html`
- **確認済み問題**: `layout.js` や `particles.js` に `defer` が付かないページがあり、ページ共通JSも広く一括読込されている
- **影響**: 初期描画ブロック、不要JSの解析コスト増加
- **対応方針**: 基本は `defer`、ページ固有処理は条件付き実行に分離する

```html
<script src="assets/js/layout.js" defer></script>
<script src="assets/dist/scripts.min.js" defer></script>
<script src="assets/js/particles.js" defer></script>
```

```js
if (document.getElementById('blogList')) {
  import('./blog-list.js');
}
```

## 4. MEDIUM優先度改善提案

### 改善 #M1 | `portfolio_0001.html` の JSON-LD `datePublished` を実値にする
- **対象**: `WebSite\portfolio\portfolio_0001.html`（同系ページ含む）
- **確認済み問題**: `"datePublished": ""` の空文字になっている
- **影響**: 構造化データ品質低下、公開日ベースの理解ができない

```html
  "dateModified": "2024-03-08"
```

### 改善 #M2 | `footer.html` の `mailto:` から `target="_blank"` を外す
- **対象**: `WebSite\partials\footer.html`
- **確認済み問題**: メールリンクに `target="_blank"` が付いている
- **影響**: メールクライアント起動導線として不自然で、不要な新規タブ挙動を招く
- **対応方針**: `mailto:` だけ通常遷移にする。必要なら `aria-label` も付ける

```html
<a href="mailto:pankun.eng@gmail.com" aria-label="PanKUNへメールを送る">
```

### 改善 #M3 | ブログ記事の TOC ボタンに `aria-expanded` / `aria-controls` を付ける

```html
  type="button"

  aria-controls="post-toc"
```

```js
const tocToggle = document.querySelector('.toc-toggle');
const toc = document.getElementById('post-toc');

tocToggle.addEventListener('click', () => {
  const isOpen = toc.classList.toggle('is-open');
  tocToggle.setAttribute('aria-expanded', String(isOpen));

```

### 改善 #M4 | `prefers-color-scheme` と `data-theme` を両立させる
- **対象**: `WebSite\assets\css\base.css`, `WebSite\assets\css\layout.css`
- **確認済み問題**: ダークテーマ前提のCSSはあるが、OS設定連動やテーマ切替設計が未整備
- **影響**: 将来のライトテーマ実装やアクセシビリティ調整が難しい
- **対応方針**: トークンを `data-theme` と `prefers-color-scheme` の両方で制御可能にする

```css
:root {
  --color-bg: #ffffff;
  --color-text: #111827;
}

@media (prefers-color-scheme: dark) {
  :root {
    --color-bg: #0d111c;
    --color-text: #e2e8f0;
  }
}

html[data-theme="dark"] {
  --color-bg: #0d111c;
  --color-text: #e2e8f0;
}
```

### 改善 #M6 | ナビゲーションへ `aria-current="page"` を実装する
- **対象**: `WebSite\partials\header.html`, `WebSite\assets\js\layout.js`
- **確認済み問題**: 見た目の `.active` は付いても、現在地が支援技術へ公開されていない
- **影響**: ナビゲーションの意味情報が不足する
- **対応方針**: active化と同時に `aria-current` を付与し、非アクティブからは削除する

```js
navLinks.forEach((link) => {
  const isCurrent = cleanTarget === currentPath;
  link.classList.toggle('active', isCurrent);
  if (isCurrent) {
    link.setAttribute('aria-current', 'page');
  } else {
    link.removeAttribute('aria-current');
  }
});
```

## 5. LOW優先度改善提案

### 改善 #Low1 | `href="#"` の ENリンクを実URLへ置き換える
- **対象**: `WebSite\partials\header.html`（必要に応じて `header_en.html` も）
- **確認済み問題**: 言語切替リンク初期値が `#` のため、JS失敗時は英語版へ遷移できない
- **影響**: 多言語導線の信頼性が落ちる
- **対応方針**: 可能ならビルド時に実URLを埋める。難しい場合でも `data-lang-path` を用意する

```html
<a href="https://breadmotion.github.io/WebSite/en/index.html" class="lang-option lang-switch">
  EN
</a>
```

### 改善 #Low2 | 見出しと本文サイズを `clamp()` でレスポンシブ化する
- **対象**: `WebSite\assets\css\base.css`
- **確認済み問題**: `h1`〜`h4` のサイズがブレークポイント切替中心で、滑らかな追従ではない
- **影響**: 中間幅端末で少し硬い印象になりやすい
- **対応方針**: 主要見出しを `clamp()` ベースへ置換する

```css
h1 { font-size: clamp(2rem, 4vw, 3.5rem); }
h2 { font-size: clamp(1.6rem, 3vw, 2.5rem); }
p  { font-size: clamp(0.98rem, 1.4vw, 1.05rem); }
```

### 改善 #Low3 | ポートフォリオ詳細にスクリーンショットを追加する
- **対象**: `WebSite\portfolio\portfolio_0001.html`
- **確認済み問題**: 作品説明はあるが視覚情報が少なく、成果物の説得力を出しにくい
- **影響**: 作品理解・問い合わせ転換率に影響
- **対応方針**: 1作品あたり最低3枚、役割がわかる alt 付きで掲載する

```html
<section class="work-gallery" aria-labelledby="gallery-title">
  <h2 id="gallery-title">スクリーンショット</h2>
  <img src="../assets/img/reimei-scene-01.webp" alt="温泉旅館の廊下を一人称視点で探索している場面" loading="lazy">
  <img src="../assets/img/reimei-scene-02.webp" alt="異変発見の判断に使う案内表示のクローズアップ" loading="lazy">
</section>
```
